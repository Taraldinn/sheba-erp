# OLT Chassis, ONU Inventory & Reconciliation

`IMPLEMENTED`

Implemented in **Phase 15**, this subsystem deepens fiber operations across the entire PON infrastructure:

```
POP
 ↓
OLT (GPON / EPON Chassis)
 ↓
PON Port (1:64 / 1:128 Splitter)
 ↓
ONU (Subscriber Optical Network Unit)
 ↓
Customer Account
```

---

## 1. Core Capabilities

1. **OLT Operational Dashboard (`/olt`)**:
   - Hardware chassis metrics (CPU, temperature, memory, uptime).
   - Port utilization across all PON interfaces.
   - Optical signal distribution histogram (Good, Warning, Critical, LOS).
2. **Live ONU Inventory & Discovery**:
   - Discovers connected ONUs directly from OLT chassis.
   - Captures Serial Number, MAC address, PON interface, Distance (meters), and optical RX/TX levels.
3. **Automated ONU Matching Engine (`autoMatchONUs`)**:
   - Scans unassigned or newly attached ONUs on PON ports.
   - Auto-matches them to ERP customers by matching customer MAC addresses or serial numbers.
   - Supports preview (`dry_run=true`) and one-click batch application (`dry_run=false`).
4. **OLT ↔ ERP Reconciliation**:
   - Performs a complete bidirectional audit between hardware state and ERP database records.
   - Categorizes every record into:
     - `MATCHED`: Both ERP and OLT agree on ONU binding and status.
     - `MISSING_IN_OLT`: ONU exists in ERP but is offline or unacknowledged by the OLT.
     - `UNKNOWN_IN_ERP`: Physical ONU detected on OLT PON port with no corresponding ERP customer record.
     - `BINDING_MISMATCH`: Serial number or MAC bound to a different customer in ERP than provisioned on OLT.
     - `OPTICAL_ALARM`: Signal level dropped below critical optical thresholds (e.g. `< -27 dBm`).
5. **Physical Interventions**:
   - Remote ONU reboot via OMCI/OAM commands.
   - Binding / unbinding customer assignments with full audit tracking.

## 2. API Endpoints

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/v1/network/olt-reconciliation/runs/` | Lists historical OLT audit runs and summary mismatch counts. |
| `POST` | `/api/v1/network/olt-reconciliation/<olt_id>/trigger/` | Triggers a live hardware audit against an OLT and returns categorized anomalies. |
| `POST` | `/api/v1/network/onus/auto-match/` | Runs auto-matching algorithm between unassigned ONUs and ERP customers (`dry_run` supported). |
| `POST` | `/api/v1/network/onus/<onu_id>/reboot/` | Triggers a remote OMCI reboot through the OLT client. |
| `POST` | `/api/v1/network/onus/<onu_id>/bind/` | Binds an unassigned ONU to an ERP customer. |
| `POST` | `/api/v1/network/onus/<onu_id>/unbind/` | Safely disassociates an ONU from a customer record. |

## 3. Optical Power Thresholds

| Signal Range (RX Power) | Classification | Action |
| :--- | :--- | :--- |
| `-14.0 dBm` to `-24.0 dBm` | **Optimal / Good** (Green) | Normal operating conditions |
| `-24.1 dBm` to `-27.0 dBm` | **Marginal / Warning** (Yellow) | Inspect splice trays, patch cords, or dirty fiber ends |
| `< -27.1 dBm` | **Critical / Optical Alarm** (Red) | High packet loss risk; dispatch fiber maintenance team |
| `0.0 dBm` / `N/A` | **Loss of Signal (LOS)** (Gray) | Fiber cut or subscriber ONU powered off |
